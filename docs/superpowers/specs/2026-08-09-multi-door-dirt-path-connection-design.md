# 다중 문 흙길 중앙 연결 설계

## 목표

문이 두 개 이상 생성된 던전 방에서 각 문의 흙길을 방 중앙까지 연장해 모든 길이 하나의 연속된 길로 보이게 한다. 문 조합에 따라 반대편 두 문은 직선, 인접한 두 문은 L자, 세 문은 T자, 네 문은 십자 형태가 된다.

이번 단계는 다중 문 연결만 다룬다. 문이 하나뿐인 방에 `Dirt_Path_Horizontal_Standalone_01` 또는 `Dirt_Path_Vertical_Standalone_01`을 적용하는 작업은 사용자의 시각 확인 이후 별도 단계에서 진행한다.

## 변경하지 않는 영역

- `DungeonLayout`의 방 배치, 방 종류와 문 방향 결정
- `RoomShape`의 44×30 크기와 6유닛 문 너비
- 문 Trigger, 전투 중 출구 잠금과 방 전환
- 문 바깥쪽 흙길 한 장의 위치와 역할
- 문이 하나뿐인 방의 현재 흙길 표시
- 사용자가 수정 중인 `NormalRoomTemplate_Example.prefab`

## 선택한 방식

기존 512×512, 64 PPU의 가로·세로 흙길 스프라이트를 8×8유닛 간격으로 반복 배치한다. 스프라이트를 길게 늘이지 않으므로 손그림 질감과 가장자리 비율이 유지된다. 최초 구현에서는 중앙에서 직선 Sprite를 겹쳤지만, 시각 확인 뒤 아래의 전용 중앙 합류부 Sprite 방식으로 보완한다.

다른 후보였던 스프라이트 Stretch 방식은 붓 자국과 경계 굴곡이 변형되므로 제외한다. 방향별 모서리·T자·십자 PNG 방식은 시각 품질은 높지만 현재 단계에 필요한 리소스와 조합 관리가 과도해 제외한다.

## 생성 규칙

`RoomBuilder.CreateDoorPaths`는 `RoomShape.DoorOpenings`의 수를 확인한다.

1. 모든 문은 현재와 같이 경계 안쪽과 바깥쪽에 첫 흙길 타일을 만든다.
2. 문이 하나이면 추가 타일을 만들지 않는다.
3. 문이 두 개 이상이면 각 문의 안쪽 방향으로 8유닛 간격의 타일을 추가한다.
4. 마지막 타일은 방 중앙축을 덮을 때까지 배치한다. 방 크기가 타일 크기의 정수배가 아니므로 중앙에서 일부 겹치는 것을 허용해 틈을 막는다.
5. 북·남 문은 세로 스프라이트, 동·서 문은 가로 스프라이트만 사용한다.
6. 가로와 세로 길이 중앙에서 겹치면 그 합성 결과가 L자, T자 또는 십자 합류부가 된다.

추가 타일은 기존 문 앞 타일과 구분되는 일관된 이름을 사용한다. 생성 순서는 문의 열거 순서와 문에서 중앙으로 향하는 거리 순서로 고정해 같은 방 입력에서 항상 같은 계층을 만든다.

## 실패 처리

기존 가로·세로 흙길 스프라이트를 불러오지 못하면 현재와 동일하게 `InvalidOperationException`을 발생시킨다. 잘못된 문 방향은 `RoomShape`가 생성하지 않으므로 별도 복구 동작을 추가하지 않는다.

## 테스트

EditMode 테스트에서 다음을 검증한다.

- 북·동 두 문이 있는 방에서 두 방향의 타일 연속 구간이 중앙에서 겹친다.
- 북·남 두 문은 중앙을 통과하는 끊김 없는 세로 길을 만든다.
- 문 세 개와 네 개 조합에서도 모든 문의 안쪽 길이 중앙에 닿는다.
- 인접한 같은 방향 타일 사이의 간격이 스프라이트 크기보다 크지 않아 빈틈이 없다.
- 추가 타일은 기존 흙길 Sprite와 Sorting Order 1을 사용한다.
- 문 하나인 방의 생성 개수와 위치는 이번 단계 전후가 같다.
- 문 Trigger와 잠금 Collider의 개수 및 Renderer가 없는 기존 동작을 유지한다.

## 완료 조건

- 모든 2~4문 조합에서 흙길이 방 중앙으로 연결된다.
- 문 하나인 방에는 새 Standalone 스프라이트가 아직 적용되지 않는다.
- 던전 연결 구조와 방 이동 동작이 바뀌지 않는다.
- 관련 EditMode 테스트와 기존 던전 테스트가 통과한다.
- Unity에서 사용자가 시각적으로 확인할 수 있는 상태에서 작업을 멈추고, 명시적인 지시 전에는 단일 문 작업으로 넘어가지 않는다.

## 시각 확인 후 중앙 합류부 보완

첫 구현을 Unity에서 확인한 결과, 중앙에서 가로·세로 직선 Sprite가 겹치는 L자 합류부의 질감과 알파 경계가 어색했다. 사용자가 다음 세 전용 리소스를 제작했으므로 중앙 합류부를 전용 Sprite 한 장으로 덮는다.

- `Dirt_Path_Corner_01.png`: 기본 연결 방향 북쪽+동쪽
- `Dirt_Path_TJunction_01.png`: 기본 연결 방향 북쪽+동쪽+서쪽
- `Dirt_Path_Cross_01.png`: 네 방향 연결

세 리소스는 `512×512`, `64 PPU`, Full Rect, Bilinear, Clamp, Mip Map Off, 투명 배경 계약을 사용한다. 현재 생성된 `.meta`의 100 PPU는 적용 과정에서 64 PPU로 교정하고 `Stage1GroundTextureImporter`가 이후 재임포트에도 같은 설정을 보장한다.

`RoomBuilder`는 문이 두 개 이상일 때 방 중앙에 `Door Path Junction`을 한 장 생성한다. 기존 길의 Sorting Order 1보다 높은 Order 2로 그려 겹친 질감을 가린다.

- 북+남: 기존 세로 직선 Sprite, 회전 0도
- 동+서: 기존 가로 직선 Sprite, 회전 0도
- 북+동: Corner, 회전 0도
- 북+서: Corner, 회전 90도
- 남+서: Corner, 회전 180도
- 남+동: Corner, 회전 270도
- 북+동+서: T, 회전 0도
- 북+남+서: T, 회전 90도
- 남+동+서: T, 회전 180도
- 북+남+동: T, 회전 270도
- 네 방향: Cross, 회전 0도

단일 문 Standalone 적용은 여전히 다음 단계로 남긴다. 던전 연결 구조, 문 Trigger, 전투 잠금, 방 전환, 사용자 프리팹과 다른 씬·UI·적 에셋 변경은 수정하지 않는다.

## 단일 문 흙길 끝 겹침 보완

Standalone Sprite로 안쪽 직선 타일을 통째로 교체한 첫 시도는 취소한다. 두 Standalone PNG는 512×512 캔버스를 사용하지만 불투명 영역의 폭과 투명 여백이 기존 직선 흙길과 달라 문 앞에서 떨어진 얼룩처럼 보였다.

검토한 방식은 세 가지다.

1. Standalone으로 직선 타일 교체: 구현은 단순하지만 연결이 끊겨 제외한다.
2. 기존 직선과 폭이 정확히 맞는 전용 끝 조각 재제작: 시각 품질은 가장 높지만 추가 리소스 제작이 필요하므로 보류한다.
3. 기존 직선 위에 Standalone 끝 조각 겹치기: 현재 리소스를 재사용하면서 직선 절단면을 가릴 수 있어 이번 단계의 선택안으로 확정한다.

### 생성 규칙

문이 정확히 하나인 방에서만 다음 순서로 생성한다.

1. 기존 안쪽 `Door Path {Side}`와 바깥쪽 `Door Path {Side} Outer`를 기존 직선 Sprite, Sorting Order 1, 기존 위치에 그대로 생성한다.
2. `Door Path {Side} Standalone`을 문 중심에서 방 안쪽으로 9유닛 떨어진 곳에 추가한다. 기존 안쪽 직선 타일과 캔버스 기준 약 3유닛 겹친다.
3. 북·남 문은 세로 Standalone을 사용하고 X축만 1.2배 확대한다.
4. 동·서 문은 가로 Standalone을 사용하고 Y축만 1.2배 확대한다.
5. Standalone은 Sorting Order 2로 그려 직선 타일의 방 안쪽 절단면을 위에서 가린다.
6. 문이 두 개 이상인 방에는 Standalone을 만들지 않고 기존 Extension과 중앙 Junction 규칙만 사용한다.

### 실패 처리와 영향 범위

단일 문 방에서 필요한 Standalone Sprite를 불러오지 못하면 기존 흙길과 같은 `InvalidOperationException`을 발생시킨다. `DungeonLayout`, `RoomShape`, 문 Trigger, 전투 잠금, 방 전환과 방 시드는 변경하지 않는다. Standalone에는 Collider를 만들지 않는다.

### 테스트와 완료 조건

EditMode 테스트에서 상·하·좌·우 단일 문 각각에 대해 다음을 검증한다.

- 안쪽과 바깥쪽 타일은 기존 직선 Sprite와 위치를 유지한다.
- Standalone은 안쪽 9유닛 위치, 방향별 Sprite, 교차축 1.2배, Sorting Order 2를 사용한다.
- Extension과 Junction은 생성되지 않는다.
- 다중 문 방에는 Standalone이 생성되지 않는다.
- 흙길 임포트 계약은 Sprite Single, 64 PPU, Clamp, Bilinear, Mip Map Off, 투명 배경, Full Rect, 최대 512px를 유지한다.

관련 EditMode와 `DungeonRunnerPlayModeTests`가 통과하면 Unity 시각 확인 단계에서 중지한다. 커밋과 푸시는 사용자가 별도로 요청할 때만 수행한다.
