# Stage1 벽 숲 — Tree 스프라이트로 교체 설계

## 배경

기존 `WallForestDecorator`는 `Assets/Resources/Stage1/Wall/wall_forest.png`(3x3, 방향별 코너/변 스프라이트)를 회전·신축시켜 벽을 따라 빈틈없이 채웠다. 실제 에디터 육안 QA에서 이 방식이 의도한 만큼 자연스럽지 않다는 피드백을 받았고, 대신 `Assets/Resources/Stage1/Wall/Objects.png`(Top-Down 2D RPG Assets Pack에서 가져온 공용 시트)에 이미 들어있는 `Tree 0`~`Tree 3` 서브스프라이트(각 16x16px, spritePixelsToUnits=16 → 1x1 유닛)로 벽을 다시 구성하기로 했다.

네 스프라이트는 모두 정사각형이고 방향성이 없는 낱개 오브젝트 아이콘이라, 기존처럼 벽 방향에 맞춰 회전시킬 필요가 없다 — 오히려 회전시키지 않는 것이 요구사항이다.

## 목표

- `wall_forest.png` 기반 로직을 `Objects.png`의 `Tree 0`, `Tree 1`, `Tree 2`, `Tree 3` 기반으로 교체한다.
- 북/남쪽 벽과 동/서쪽 벽을 서로 다른 방식으로 꾸민다(아래 참고). `RoomKind` 분기는 여전히 없다 — 방 종류가 아니라 변의 방향(North/South vs East/West)에 따라서만 갈린다.
- 타일은 회전하지 않는다. 늘리거나 찌그러뜨리지 않는다(신축 없음) — 원래 1x1 크기 그대로 사용한다.

### 북/남쪽 벽 — 4겹 띠 (기존 설계 그대로)

방 경계선(`shape.Bounds`)에서 방 안쪽으로 4겹 띠를 쌓는다(바깥→안쪽 순서):

1. `Tree 0` — 벽의 맨 위(가장 바깥쪽) 켜. 콜라이더 있음.
2. `Tree 1` — 벽의 몸통, 빈틈없이 채우는 메인 켜. 콜라이더 있음.
3. `Tree 2` — 벽의 옆면(정면에서 보이는 면). 콜라이더 있음.
4. `Tree 3` — 그림자. 콜라이더 없음(순수 시각 요소).

각 켜는 폭 1유닛이며 서로 겹치지 않고 이어 붙는다(경계선에서 안쪽으로 0~1, 1~2, 2~3, 3~4유닛). 벽 구간 길이에 맞춰 타일 개수/간격을 조절하되(개수 = `round(길이 / 1유닛)`) 스프라이트 자체는 늘리지 않는다 — 유기적인 이미지라 완벽한 수학적 무결점 대신 약간의 겹침/틈을 허용한다.

**경계선 바깥의 도달 불가능 영역도 채운다(2026-08-08 추가, 이후 Tree1 전용으로 정리).** 4겹 띠(Tree0~2)의 콜라이더가 이미 방 경계선 부근에서 플레이어를 막으므로, 경계선부터 실제 충돌 한계(`OutdoorRoomGeometry.SafetyPadding`, 3유닛 바깥)까지는 플레이어가 절대 도달할 수 없는데도 잔디만 보이는 죽은 구간이다. 이 구간을 `Tree 1`로만 채운다(처음엔 Tree0/Tree1을 번갈아 뒀다가, 채움 영역은 Tree1로 통일해 달라는 요청에 따라 단순화했다). 동/서쪽은 이미 자체 4겹 복제가 바깥쪽으로 뻗어 같은 역할을 하므로 이 채움은 북/남쪽에만 적용한다.

### 동/서쪽 벽 — 한 줄 패턴 + 문 캡을 방 바깥쪽으로 4겹 복제 (WallExample.png 참고, 2026-08-08 수정 → 4겹 복제 추가)

동/서쪽은 먼저 **한 줄**짜리 패턴을 만든다: 기본값은 전부 `Tree 1`. 그 변에 문이 없으면 corner-to-corner 전체가 `Tree 1`뿐이다.

그 변에 문이 있으면(양쪽으로 벽이 나뉜다) **문과 맞닿는 끝만** 다르게 캡을 씌운다:

- 문 **아래쪽** 구간(문에 닿는 끝이 반대쪽 끝-방 모서리-보다 y가 큼, 즉 아래에서 올라와 문 바로 밑에서 끝나는 구간): 문에 가장 가까운 타일 1칸을 `Tree 0`.
- 문 **위쪽** 구간(문에 닿는 끝이 반대쪽 끝보다 y가 작음): 문에 가장 가까운 2칸을 안쪽(문에 더 가까운 쪽)부터 `Tree 3` → `Tree 2`.
- 문과 무관하게 방 모서리에서 끝나는 지점은 캡 없이 그냥 `Tree 1`로 끝난다.

이 캡 배치는 East/West 어느 쪽이든 같은 규칙(문에 닿는 끝점과 반대쪽 끝점의 world Y 비교)으로 판단한다 — 어느 변인지에 따라 분기하지 않는다.

**이 한 줄 패턴을 4겹으로 복제한다(2026-08-08 추가).** 북/남쪽처럼 방 안쪽으로 복제하면 콜라이더가 플레이어의 이동 가능 공간을 갉아먹으므로, 대신 **방 바깥쪽**(플레이어가 갈 수 없는 방향)으로 복제한다. 원래 자리(경계선, 오프셋 0)는 그대로 두고 — 기존 단일 줄과 동일하게 경계선에서 정확히 플레이어를 막는다 — 나머지 세 겹만 `-inward`(바깥) 방향으로 1, 2, 3유닛 떨어뜨린다. 스프라이트 선택(Tree0/1/2/3 캡 포함)은 along-wall 위치별로 한 번만 계산하고, 4겹 모두 같은 스프라이트를 쓴다(북/남쪽처럼 깊이마다 다른 스프라이트를 쓰지 않는다).

**정렬 순서.** 동/서쪽 밴드가 방 바깥쪽으로 뻗으면서 북/남쪽 밴드와 모서리 부근에서 겹칠 수 있다. 동/서쪽이 항상 위에 그려지도록 `SideWallOrder = 3`을, 북/남쪽에는 기존 `ForestOrder = 2`를 쓴다.

## 범위 밖

- 기존 Task 4의 좌우 반전 + 높이 지터(다양성 부여) 기능은 제거한다 — 4개의 서로 다른 고정 스프라이트를 층으로 쌓는 구조라 반전/지터가 어울리지 않는다는 사용자 판단.
- 콜라이더가 실제 `RoomBuilder.CreateSafetyBoundary`(방 경계 3유닛 바깥의 EdgeCollider2D)를 대체하지 않는다 — 그대로 바깥쪽 보험으로 남긴다.
- `wall_forest.png` 리소스 자체는 삭제하지 않는다(사용하지 않게 될 뿐).

## 설계

### 스프라이트 로딩

`Objects.png`는 `wall_forest.png`와 동일하게 Sprite Mode: Multiple로 슬라이스된 시트라 `Resources.Load<Sprite>("경로/이름")`으로 서브스프라이트를 직접 로드할 수 없다. 기존과 같은 패턴을 그대로 쓴다:

```csharp
Sprite[] allSprites = Resources.LoadAll<Sprite>("Stage1/Wall/Objects");
Sprite sprite = Array.Find(allSprites, s => s.name == "Tree " + index); // index: 0~3
```

### 타일 배치 — 공통

`shape.Walls[i]`는 손그림 느낌을 위해 중간 지점들이 안쪽으로 흔들리는(wobble) 폴리라인이다(`RoomShape.WobbleWall`). 하지만 나무 벽은 곡선이 아니라 **직선**이어야 한다는 요구사항(2026-08-08 수정)에 따라, 흔들리는 중간 점은 전부 무시하고 그 폴리라인의 **양 끝점만**(`wall[0]`, `wall[^1]`) 사용한다 — 이 두 점은 코너 또는 문 경계이며 `WobbleWall`이 항상 흔들지 않는 지점이라 정확히 직선의 기준으로 쓸 수 있다.

이 직선 구간(`from`→`to`)에서 앵커(타일 중심 후보 위치)를 계산하는 방식은 북/남과 동/서가 같다:

1. `length = Vector2.Distance(from, to)`, `count = max(1, round(length / 1f))`, `slot = length / count`.
2. `direction = (to - from).normalized`.
3. 구간을 따라 `count`개의 자리에 타일 중심을 놓는다: `from + direction * (slot * (i + 0.5))`.

### 타일 배치 — 북/남쪽

각 앵커마다 그 변의 안쪽 방향(`DungeonNavigation.Inward(side)`)으로 0.5, 1.5, 2.5, 3.5유닛만큼 오프셋을 준 4개의 타일을 놓는다. 회전은 항상 0도, 스케일은 항상 `Vector2.one`.

**스프라이트 순서는 화면상 절대 방향 기준이다(2026-08-08 수정).** Tree0(맨 위)~Tree3(그림자)는 어느 벽이든 화면상 위→아래 순서로 나타나야 한다. 북쪽은 `inward`가 -y라서 레이어 인덱스가 커질수록 y가 작아지므로 레이어 인덱스를 그대로 스프라이트 인덱스로 써도 위→아래가 Tree0~3이 된다. 남쪽은 `inward`가 +y라서 레이어 인덱스가 커질수록 y가 **커진다**.

**남쪽은 Tree2/Tree3을 쓰지 않는다(2026-08-08 추가 수정 — 콜라이더 공백 버그).** 처음에는 남쪽도 스프라이트 인덱스를 `LayerCount - 1 - layer`로 단순히 뒤집어 화면상 위→아래 순서만 맞췄다. 그런데 이렇게 하면 남쪽에서 경계선에 가장 가까운 자리(플레이어가 벽을 향해 걸어가다 제일 먼저 닿는 자리)에 **콜라이더가 없는 Tree3**이 오게 되어, 그 자리만 플레이어가 나무를 밟고 지나갈 수 있었다(북쪽은 반전이 없어서 이 문제가 없다 — 북쪽의 Tree3은 이미 콜라이더가 있는 Tree0/1/2 뒤쪽, 즉 플레이어가 절대 먼저 닿지 않는 가장 안쪽 자리에 있다). 그래서 남쪽은 `layer == LayerCount - 1`(가장 안쪽, 화면상 가장 위)일 때만 Tree0을 쓰고, 나머지 세 자리(경계선 쪽)는 전부 Tree1을 쓴다 — 콜라이더가 있는 스프라이트(Tree0, Tree1)만 쓰므로 경계선부터 안쪽까지 빈틈없이 막힌다.

**북쪽도 경계선 자리는 Tree0 대신 Tree1을 쓴다(2026-08-08 추가).** 북쪽은 원래 콜라이더 공백 버그가 없었지만(Tree0이 이미 경계선에 콜라이더를 갖고 있었다), 사용자 요청에 따라 `layer == 0`(경계선) 자리도 Tree0 대신 Tree1로 통일했다. 결과적으로 북쪽 띠는 Tree0을 전혀 쓰지 않고 Tree1(경계선+그 다음 자리)→Tree2→Tree3 순서가 된다.

### 타일 배치 — 동/서쪽

벽 폴리라인(문이 있으면 두 개의 하위 폴리라인) 전체를 훑어 앵커 목록을 하나로 모은다(오프셋 없음 — 앵커 위치 자체가 layer 0 자리다). 기본값은 전부 `Tree 1`. 그 변에 문이 있으면(`RoomShape.TryGetDoor`) 이 폴리라인의 양 끝점 중 문 중심(`DoorOpening.Center`)에 더 가까운 쪽을 찾아 "문에 닿는 끝"으로 삼고, 그 끝점의 world y를 반대쪽 끝점과 비교해 위/아래 구간 여부를 판정한 뒤 위에서 설명한 캡을 앵커 목록의 해당 끝(인덱스 0 또는 `count-1`)에 적용한다.

각 앵커마다(스프라이트 선택은 앵커당 한 번만) `layer = 0..3`에 대해 `anchor + (-inward) * layer` 위치에 타일을 놓는다 — layer 0은 오프셋이 0이라 앵커 자리(경계선) 그대로고, layer 1~3은 방 바깥쪽으로 1, 2, 3유닛 떨어진다.

### 타일 배치 — 네 모서리 바깥 대각선 사각지대 (2026-08-08 추가)

북/남쪽의 경계 바깥 채움은 x가 `[xMin, xMax]` 범위만 덮고, 동/서쪽의 4겹 복제는 y가 `[yMin, yMax]` 범위만 덮는다. 그래서 x와 y가 둘 다 경계 바깥인 대각선 구석(예: 북동쪽 모서리 바깥의 사각형 구간)은 둘 중 어느 채움도 닿지 않는 사각지대였다. `Decorate` 마지막에 한 번, 방 네 모서리마다 `SafetyPadding × SafetyPadding` 크기의 `Tree 1` 격자를 대각선 바깥쪽으로 채워 이 사각지대를 없앤다.

### 콜라이더

`Tree 0`~`Tree 2`는 `RoomBuilder`가 만드는 것과 같은 방식(정적 `Rigidbody2D` + `BoxCollider2D`, 크기는 스프라이트 bounds)을 그대로 쓴다. `Tree 3`는 `SpriteRenderer`만 붙이고 콜라이더/Rigidbody2D를 만들지 않는다. 이 규칙은 북/남·동/서·모서리 채움 모두 동일하다(`treeIndex < 3`이면 콜라이더).

### 계층 구조

기존과 동일하게 `parent` 아래 `"Wall Forest"` 오브젝트 하나에 모두 정리한다.

## 테스트 변경 범위

`WallForestDecoratorTests.cs`:

- 북/남쪽: `Tree 0`~`Tree 3` 4겹이 모두 나타나는지, 서로 정확히 1유닛씩 안쪽으로 떨어져 있는지.
- 동/서쪽: 문이 없으면 `Tree 1`만 있는지. 문이 있으면 문 아래쪽 구간의 문과 가장 가까운 타일이 `Tree 0`인지, 문 위쪽 구간의 가장 가까운 두 타일이 `Tree 3`→`Tree 2` 순인지, 나머지는 `Tree 1`인지.
- 콜라이더: `Tree 0`/`Tree 1`/`Tree 2`는 Static Rigidbody2D + BoxCollider2D를 갖고, `Tree 3`는 갖지 않는지(북/남·동/서 공통).
- 문 간격 안에는 어떤 타일도 생기지 않는지.
- 모든 타일의 회전이 0이고 스케일이 `Vector2.one`인지(회전 없음 요구사항).
- 북쪽/동쪽 벽 각각 같은 변을 따라가는 타일들이 흔들림 없이 정확히 일직선인지(직선 배치 요구사항, 2026-08-08 추가). 북쪽에서 검증하면 남쪽도 같은 코드 경로를 타므로 별도 테스트 없이 함께 보장된다. 동/서도 같은 논리로 동쪽만 검증한다.

전체 테스트 스위트는 실행하지 않는다. `WallForestDecoratorTests`에 좁힌 필터만 사용한다.
